# Архітектурні рішення (ADR) для Louise Translator (Android)

> Згідно з Маніфестом міграції (Фаза 4: `04-architecture.md`).  
> Документування стратегічних технічних рішень та вибору стека.

---

## ADR-001: Вибір стека реалізації для Android

### Статус:
Прийнято (Accepted).

### Контекст:
Louise Translator на Windows написаний на мові Rust (UI: Slint).  
При перенесенні на Android існує два підходи:
1. **Чистий Slint + Rust NDK**: єдиний код Slint на обох платформах.
2. **Kotlin + Jetpack Compose (з чистим доменом логіки перекладу)**:
   - Android-специфічні API (`PROCESS_TEXT`, Floating Service, `WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY`, системний `ClipboardManager`, `MediaProjection` для скріншотів, Google ML Kit) мають першокласну нативну підтримку в Kotlin і Jetpack Compose.
   - Slint на Android наразі вимагає обгортки Winit activity, що ускладнює створення нативних floating overlay та системних текстових сервісів без підняття повного вікна activity.

### Рішення:
- Обрати **нативний сучасний стек Android: Kotlin 2.x + Jetpack Compose + Coroutines / Flow**.
- Бізнес-контракти (API Google Translate, DeepL API, Edge TTS, евристики автовизначення мов) переносяться з Rust 1:1 зі збереженням поведінки та алгоритмів.
- Дозволяє створити надлегкий APK (< 5–8 МБ), нульове споживання батареї у фоні, миттєвий відгук системного меню «Louise» та апаратне шифрування ключів через `Android Keystore`.

### Наслідки:
- **Позитивні**:
  - Бездоганна інтеграція з системним виділенням тексту в будь-якому додатку Android без милиць.
  - Повна свобода накладання плаваючого вікна поверх інших додатків.
  - Офлайн OCR з коробки через Google ML Kit Text Recognition без необхідності тягнути важкий Tesseract C++ двигун.
- **Компроміси**:
  - UI верстається за допомогою Jetpack Compose за тими самими дизайн-токенами (`#101010`, `JetBrains Mono`), а не компілюється безпосередньо з `.slint`.

## ADR-002: Модель плаваючого інтерфейсу (Floating Window / BottomSheet)

### Статус:
Прийнято (Accepted).

### Контекст:
Користувачеві на смартфоні незручно перемикатися в окремий повноцінний додаток, коли він читає статтю в браузері чи листується в чаті. Головна перевага Louise на ПК — поява віконця біля курсора без втрати контексту.

### Рішення:
- Реалізувати два режими:
  1. **BottomSheet Modal Activity (без фонового сервісу)**: при виклику через меню `Process Text` знизу плавно з'являється компактна шторка Louise, поверх поточної програми. Не потребує дозволів `SYSTEM_ALERT_WINDOW` (працює на будь-якому пристрої одразу після встановлення).
  2. **Floating Bubble Overlay (опціональний плаваючий віджет)**: для користувачів, які хочуть перекладати весь екран або мати постійну плаваючу іконку на екрані.

## ADR-003: Офлайн розпізнавання тексту (Screen OCR) на Android

### Статус:
Прийнято (Accepted).

### Контекст:
На Windows Louise використовує `Windows.Media.Ocr` — рідний системний офлайн рушій. На Android немає WinRT API.

### Рішення:
- Використовувати **Google ML Kit Text Recognition** (`com.google.mlkit:text-recognition`).
- Модель працює на 100% локально на пристрої (на NPU/CPU), не передає зображення в інтернет, підтримує латиницю, кирилицю та інші скрипти з надзвичайно високою точністю та швидкістю (< 50 мс на сучасних смартфонах).
